  <action>
    Create `ingest/Dockerfile` with a two-stage build (per OPS-05, CONTEXT.md locked decision):

    ```dockerfile
    # Build stage
    FROM golang:1.22-alpine AS builder

    WORKDIR /app

    # Cache dependency download (Pitfall 5: separate go.mod copy from source copy)
    COPY go.mod go.sum ./
    RUN go mod download

    # Build static binary
    COPY . .
    RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /ingest ./cmd/ingest

    # Runtime stage
    FROM alpine:3.19

    # Non-root user with uid 1000 (matches K8s runAsNonRoot: true, runAsUser: 1000)
    RUN adduser -D -u 1000 ingest

    # ca-certificates needed for TLS connections (MinIO with MINIO_SECURE=true)
    RUN apk add --no-cache ca-certificates

    COPY --from=builder /ingest /ingest

    USER ingest

    EXPOSE 8080

    ENTRYPOINT ["/ingest"]
    ```

    Key details:
    - `CGO_ENABLED=0` produces a static binary with no libc dependency
    - `-ldflags="-s -w"` strips debug info and DWARF symbols, reducing binary ~30%
    - Two-step COPY pattern: `go.mod go.sum` first → `go mod download` → then source. This caches deps unless go.mod changes (avoids Pitfall 5: 60s+ rebuilds on code-only changes)
    - `adduser -D -u 1000 ingest` creates non-root user matching K8s security context
    - `ca-certificates` package for TLS connectivity
    - Final image ~15-20MB (alpine base + static binary + ca-certs)
  </action>

    Add the `ingest` service block to `docker-compose.yml` AFTER the existing `worker` service block and BEFORE the `volumes:` section. The service follows the existing patterns in the file but uses `env_file` per CONTEXT.md locked decision ("same .env file").

    Insert this block after the `worker:` service (after line ~109, before `volumes:`):

    ```yaml
      # Go Ingest Service — replaces POST /api/v1/files
      ingest:
        build:
          context: ./ingest
          dockerfile: Dockerfile
        ports:
          - "8080:8080"
        environment:
          DATABASE_URL: ${DATABASE_URL:-postgresql+asyncpg://postgres:postgres@postgres:5432/malscan}
          MINIO_ENDPOINT: minio:9000
          MINIO_ACCESS_KEY: minioadmin
          MINIO_SECRET_KEY: minioadmin
          RABBITMQ_URL: amqp://guest:guest@rabbitmq:5672/
          PORT: 8080
          LOG_LEVEL: INFO
        depends_on:
          postgres:
            condition: service_healthy
          minio:
            condition: service_healthy
          rabbitmq:
            condition: service_healthy
    ```

    **Why `environment:` block instead of `env_file:`:**
    The existing `api` and `worker` services in docker-compose.yml both use inline `environment:` blocks with hardcoded values and `${VAR:-default}` syntax. To match the existing pattern and avoid requiring a `.env` file to exist (which would break `docker compose up` for new clones), use the same inline approach. The Go config strips `+asyncpg` from DATABASE_URL at parse time, so passing the Python-format URL is correct.

    **Key values:**
    - `DATABASE_URL` uses same `${DATABASE_URL:-...}` pattern as `api` service (with `+asyncpg` — Go strips it)
    - `MINIO_ENDPOINT: minio:9000` — Docker service name, NOT localhost
    - `MINIO_ACCESS_KEY: minioadmin` / `MINIO_SECRET_KEY: minioadmin` — matches MinIO service defaults
    - `RABBITMQ_URL: amqp://guest:guest@rabbitmq:5672/` — matches existing services
    - `PORT: 8080` — Go service port
    - `depends_on` uses `condition: service_healthy` for all three infra services (postgres, minio, rabbitmq all have healthchecks defined)
  </action>
