# OpenSpec: 儲存空間與大檔案上傳優化 (Storage & Large File Optimization)

**狀態:** Archived
**日期:** 2026-03-07
**目標:** 在不縮減 100MB 單檔上傳上限的前提下，透過縮短保留時間機制，確保 50GB 本地儲存空間不會被塞滿，維持系統長期的穩定運行。

## 1. 背景與痛點 (Context)
1. **大檔上傳支援**: 先前專案為了支援分析大型安裝檔與壓縮檔，將單一檔案上傳上限設定為 100MB。
2. **硬碟空間耗盡風險**: 實體主機的 MinIO 分配空間約為 50GB。在原本 `7 天保留期` 的設定下，若有心人士或正常業務流量中包含大量 100MB 滿檔，最快 512 個檔案（約每天 73 個大檔）就會將硬碟空間完全塞滿。
3. **系統中斷**: 一旦 MinIO 空間耗盡，API 會無法接收新檔案 (HTTP 500)，Worker 也無法正常從 MinIO 下載暫存檔案進入掃描階段，造成服務全面停擺。

## 2. 變更項目 (Completed Changes)

### A. 儲存層生命週期 (Lifecycle) 調整
*   修改 `backend/src/malscan/storage.py` 中的 `init_buckets` 函數。
*   將 Bucket 生命週期規則 (`LifecycleConfig`) 中的過期天數從 `Expiration(days=7)` 修改為 `Expiration(days=1)`。
*   更新 `rule_id` 與日誌 (`log.info`) 以反映最新的 1 天刪除政策。

## 3. 預期效益 (Expected Benefits)
*   **維持業務彈性**：繼續維持 100MB 的大檔案支援能力。
*   **系統防禦力提升**：最大儲存數量大幅提升至「每天 500 個 100MB 大檔」都不會造成系統磁碟滿載，確保基礎設施不會因為暫存檔而崩潰。
*   **精準資源控制**：無用且已分析完成的 `.bin` 檔案能更快釋放空間，將儲存資源留給當下排隊中或真正需要被處理的任務。
